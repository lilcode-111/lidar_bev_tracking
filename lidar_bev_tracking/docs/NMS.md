NMS 在自动驾驶感知中的作用

NMS（Non-Maximum Suppression，非极大值抑制）用于删除同一目标附近的重复检测框，只保留置信度最高的框。

感知模型为什么会输出多个框：
目标检测模型通常会在很多 BEV 网格、anchor 或中心点附近产生候选框。同一辆车附近可能有多个位置都认为“这里有车”，因此会输出多个相近的预测框。

例子：
box A: car, score=0.92
box B: car, score=0.68
box C: car, score=0.55

这些框可能都在描述同一辆车。

NMS 的基本逻辑：
1. 按 score 从高到低排序
2. 先保留最高分框
3. 计算它和其他同类别框的 IoU
4. 如果 IoU 大于阈值，认为是重复框，删除低分框
5. 对剩余框重复上述过程

例如：
box A: score=0.92
box B: score=0.68
IoU(A, B)=0.75
阈值 iou_threshold=0.3

因为 0.75 > 0.3，所以 B 被认为是 A 的重复框，最终保留 A，删除 B。

注意：
NMS 中的 IoU 是 pred box 和 pred box 之间计算，用来判断预测框是否重复。
检测评价中的 IoU 是 pred box 和 GT box 之间计算，用来判断 TP、FP、FN。

一句话总结：
NMS 用 IoU 判断预测框之间是否重复，并保留高置信度框，把模型输出的大量候选框整理成最终检测结果。


因为目标检测模型在推理时，通常不是“一眼就输出一个最终框”，而是会先产生大量候选框，然后再筛选。
所以同一个物体附近出现多个框很常见。
原因主要有几个。
1. 模型会在很多位置尝试预测
比如 BEV 网格上，每个位置都可能预测：
这里有没有车
车的中心在哪里
长宽是多少
朝向是多少
置信度是多少
如果一辆车在某个区域附近，周围多个网格点都可能觉得：
我这里像车中心
于是就会输出多个接近的框。
2. Anchor-based 检测会有多个 anchor
很多检测模型会预设不同大小、不同朝向的 anchor。
例如在同一个位置，可能有：
小车 anchor
大车 anchor
朝向 0 度 anchor
朝向 90 度 anchor
如果目标在这里，多个 anchor 都可能被激活，产生多个框。
这些框位置很接近，分数也可能都不低。
3. Anchor-free 检测也会有邻近点重复响应
即使不用 anchor，像 CenterPoint 这类方法也会预测中心点热力图。
理想情况下目标中心只有一个峰值，但实际可能出现：
中心附近多个像素都有较高响应
于是也会产生多个候选框。
4. 模型本身有不确定性
比如点云稀疏、遮挡、远距离、小目标时，模型可能不确定目标边界。
于是可能输出：
一个偏左一点的框
一个偏右一点的框
一个角度稍微不同的框
这些框都在描述同一个目标。
5. 多类别或相近类别也可能重复
比如一个目标可能同时被认为是：
car
truck
van
这种时候也可能出现多个类别不同但位置相近的框。
普通 NMS 通常只压同类别框；如果要处理跨类别重复，需要 class-agnostic NMS 或其他策略。
所以检测模型原始输出通常长这样：
一辆车附近：
box A score=0.92
box B score=0.81
box C score=0.68
它们都围着同一辆车。
NMS 做的事情就是：
保留最高分 box A
删除和 A 高度重叠的 box B、box C
