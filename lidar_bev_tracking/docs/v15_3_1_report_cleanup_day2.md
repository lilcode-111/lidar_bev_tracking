# v15.3.1 Report Cleanup Day 2

## Change

Batch candidate-conversion diagnostics now use `candidate_conversion.evidence`
as the only GT-level source. The duplicated `gt_records` output is no longer
generated by `build_variant_diagnostics`. The canonical records are persisted
under `candidate_conversion_evidence`, so removing the duplicate does not lose
frame/GT-level branches or downstream attribution.

Distance analysis also reads the canonical evidence, including its preserved
`matched_by_iou` values for IoU 0.50 and 0.25. Terminal-state aggregation uses
the canonical `terminal_state` field and is emitted as `terminal_state_counts`.

## Compatibility

Detection, NMS, evaluation, and legacy frame-report construction are unchanged.
This day only changes diagnostic aggregation and output shape.
