# 15.4 Phase-1 Day1: schedule and evidence identity

Day1 freezes the four intensity thresholds, the only permitted effective-config
difference, the 25/100-frame manifests, and the fixed delta-22 identity list. It
does not run or inspect a new T0/T1/T2/T_off comparison.

The evidence inventory intentionally records two historical gaps:

- the 15.3.2 artifact stores O3 point counts and IoU, but not the complete O3
  `raw_lidar_point_index` set;
- the A0-prime 100-frame declaration stores aggregate metrics, but not the full
  frame/GT/candidate identity sets required by the new replay contract.

Consequently, Day1 keeps `formal_run_authorized=false`. A T0-only
materialization must fill these exact-reference gaps before any T1, T2, or
T_off formal run.

Hash semantics are explicit: manifests use canonical UTF-8/LF content,
ordered identities use compact canonical JSON, and JSON artifacts use raw file
bytes.

```bash
PYTHONPATH=src python -m unittest tests.test_v15_4_materialization_day1 -v
PYTHONPATH=src python scripts/validate_v15_4_day1.py
```
